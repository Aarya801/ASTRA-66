# ASTRA-66 — Hardware selection checklist (Phase 6)

> **No component has been selected, bought or tested, and the project is NOT flight certified.** This checklist turns
> `avionics/HARDWARE_MAPPING.md` into a per-subsystem selection sheet. It contains **no manufacturer part numbers**:
> where the repository already names an example class, that class is quoted with its source, and its datasheet has not
> been checked. Fill a sheet in only from a real datasheet, with a mentor.
>
> **Source of the existing example classes:** `avionics/electronics.csv`, generated by `build.py` from
> `documentation/generator/data_tables.py`. They are planning examples ("verify datasheets"), not selections.
> Mass figures below are the current **assumptions** in `analysis/analysis.py` (see
> `avionics/integration/avionics_mass_properties.csv`), not measurements.

How to use: copy a block per subsystem into the team's selection record, fill every row from the datasheet, then run
the bench tests in `documentation/AVIONICS_BENCH_TEST_PLAN.md`. A subsystem is "selected" only when every **evidence**
row is satisfied and a mentor has reviewed it. Until then it stays **COMPONENT TO BE SELECTED**.

## Common constraints (apply to every subsystem)

| Constraint | Value | Status |
|---|---|---|
| Logic voltage | 3.3 V (regulated); 1S LiPo 3.0–4.2 V upstream | assumption (`avionics/HARDWARE_MAPPING.md`) |
| 5 V-only parts | not acceptable without a documented level-shift / boost plan | assumption |
| Buses available | I²C, SPI, UART, ADC, GPIO **inputs** | design requirement |
| Outputs | **none**: no igniter, pyrotechnic, energetic or deployment channel may exist | safety boundary |
| Mounting | M2.5 inserts on the sled (10 bosses, 25 mm pitch) or the GPS tray (6 bosses) | CAD (`cad/parts/AV-306_electronics_sled.scad`) |
| Envelope | inside the coupler bore: sled stack max radius 30.5 mm | CAD check |
| Environment | −20…+60 °C assumed; vibration and shock not characterised | assumption |
| Documentation | public datasheet + open driver; record both in the selection sheet | requirement |

## 1. Flight computer (microcontroller board)

| Item | Requirement |
|---|---|
| Required interface | I²C + SPI + UART + ADC + GPIO inputs; free-running microsecond timer |
| Voltage / interface constraints | 3.3 V logic; USB for configuration; must not require 5 V sensors |
| Physical envelope | ≤ 21 × 8.5 × 50 mm placeholder (`cad/parts/COTS_envelopes.scad`), measure the real board with headers |
| Approximate mass budget | part of EL-AV 59 g total (assumption, covers MCU + IMU + baro + SD + radio + buzzer + wiring) |
| Mounting | M2.5 standoffs on the sled; connectors reachable with the sled fitted |
| Software interface | runs the Phase 4/5 pipeline structure (`avionics/firmware/flight_computer.py`) |
| Test required | B-01 power-up, B-02 sensor detection, B-11 timestamp consistency, B-13 long-duration logging |
| Evidence before flight use | measured loop rate ≥ 100 Hz with logging and telemetry active; measured current draw; weighed mass |
| Existing example class | "RP2040 (e.g. Raspberry Pi Pico) or ESP32-S3 dev board" — `avionics/electronics.csv`, unverified |

## 2. IMU (accelerometer + gyroscope)

| Item | Requirement |
|---|---|
| Required interface | I²C or SPI (SPI preferred at 100 Hz) |
| Voltage / interface constraints | 3.3 V; documented axis orientation; configurable full scale and output rate |
| Physical envelope | ≤ 14 × 4 × 14 mm placeholder; **placeholder position is 20.5 mm off the roll axis** — decide the final position |
| Approximate mass budget | within EL-AV 59 g (assumption) |
| Mounting | rigid, close to the roll axis if possible, axis mapping recorded in the firmware |
| Software interface | `Sensor` driver returning `imu_accel_x`, `imu_accel_y`, `imu_accel_z` (m/s², specific force) and `gyro_x`, `gyro_y`, `gyro_z` (deg/s) |
| Test required | B-03 IMU sanity (1 g checks, six orientations), B-11 timestamp consistency |
| Evidence before flight use | measured bias and noise at rest; full-scale ≥ ±16 g confirmed from the datasheet; axis mapping verified |
| Existing example class | "6-axis, ±32 g accel class (e.g. ST LSM6DSO32 breakout)" — `avionics/electronics.csv`, unverified |

## 3. Barometric pressure sensor

| Item | Requirement |
|---|---|
| Required interface | I²C or SPI |
| Voltage / interface constraints | 3.3 V; 30–110 kPa range; ≥ 20 Hz (50 Hz preferred) |
| Physical envelope | ≤ 13 × 4 × 13 mm placeholder, at the static-port station (STA 529 mm) |
| Approximate mass budget | within EL-AV 59 g (assumption) |
| Mounting | in the sealed avionics bay, shielded from light and draughts; 4 × ⌀2 mm static ports |
| Software interface | `Sensor` driver returning `barometric_pressure` (Pa) |
| Test required | B-04 pressure sanity (ambient, altitude change, syringe / bag test), B-13 |
| Evidence before flight use | measured noise at rest; measured pad-reference stability; documented static-port response |
| Existing example class | "Bosch BMP390 or TE MS5611 breakout" — `avionics/electronics.csv`, unverified |

## 4. GNSS receiver + antenna

| Item | Requirement |
|---|---|
| Required interface | UART (NMEA or documented binary protocol), ≥ 1 Hz |
| Voltage / interface constraints | 3.3 V logic; antenna connector and ground-plane needs documented; backup battery for warm start optional |
| Physical envelope | ≤ 25 × 8 × 35 mm placeholder on the payload tray, under the hatch |
| Approximate mass budget | EL-GPS 20 g including the antenna (assumption) |
| Mounting | 6 M2.5 bosses on `cad/parts/PL-202_gps_tray.scad`; sky view forward, away from the radio antenna |
| Software interface | `Sensor` driver returning `latitude`, `longitude`, `gps_altitude`, `gps_fix`, `gps_satellites` |
| Test required | B-05 GNSS acquisition (cold and warm, indoors / outdoors, inside the airframe) |
| Evidence before flight use | measured time to first fix; fix kept with the radio transmitting; weighed mass |
| Existing example class | "u-blox M8/M9/M10-class module + patch antenna" — `avionics/electronics.csv`, unverified |

## 5. Temperature sensor

| Item | Requirement |
|---|---|
| Required interface | I²C, or the barometer's internal temperature channel |
| Voltage / interface constraints | 3.3 V; −20…+60 °C |
| Physical envelope | no CAD envelope yet — add one if a separate breakout is chosen |
| Approximate mass budget | within EL-AV 59 g (assumption) |
| Mounting | in air, away from self-heating parts (regulator, radio) |
| Software interface | `Sensor` driver returning `temperature` (°C) |
| Test required | B-02 sensor detection, B-13 (drift over a long log) |
| Evidence before flight use | offset against a reference thermometer; self-heating measured |
| Existing example class | "TI TMP117 breakout or baro internal sensor" — `avionics/electronics.csv`, unverified |

## 6. Battery monitor

| Item | Requirement |
|---|---|
| Required interface | ADC input through a resistor divider |
| Voltage / interface constraints | divider must keep the ADC input inside its range at 4.2 V; high resistance to limit drain |
| Physical envelope | on the flight-computer board or a small adapter; no separate envelope yet |
| Approximate mass budget | negligible; inside EL-AV 59 g (assumption) |
| Mounting | as close to the battery connector as practical |
| Software interface | `Sensor` driver returning `battery_voltage` (V) |
| Test required | B-12 battery monitoring (calibration against a multimeter, sag under transmit) |
| Evidence before flight use | calibration curve recorded; resolution and drift stated |
| Existing example class | none: added in Phase 4 as a requirement |

## 7. Battery and power

| Item | Requirement |
|---|---|
| Required interface | 1S LiPo with protection circuit, JST-PH; 3.3 V regulator (≥ 500 mA) downstream |
| Voltage / interface constraints | 3.0–4.2 V; regulator must hold 3.3 V at the peak transmit current |
| Physical envelope | ≤ 28.8 mm wide (rod sleeves); placeholder cell 55 × 28 × 9 mm |
| Approximate mass budget | EL-BAT 27 g including the strap (assumption) |
| Mounting | `cad/parts/AV-308_battery_cage.scad`, strap-retained; connector reachable |
| Software interface | none (monitored through the battery monitor) |
| Test required | B-01 power-up, B-12 battery monitoring, B-13 endurance (existing test plan item T-10) |
| Evidence before flight use | measured pad-hold endurance with margin; retention checked under shake; charging procedure agreed |
| Mentor / range | LiPo handling, charging and transport follow the range's rules (**REQUIRES MENTOR/RANGE REVIEW**) |

## 8. Data storage (microSD or equivalent)

| Item | Requirement |
|---|---|
| Required interface | SPI socket; FAT-compatible card |
| Voltage / interface constraints | 3.3 V; sustained write above log rate × ~110 bytes per row (≥ 11 kB/s at 100 Hz) with margin |
| Physical envelope | ≤ 20 × 4.5 × 26 mm placeholder; card must be removable or the sled must come out |
| Approximate mass budget | within EL-AV 59 g (assumption) |
| Mounting | card slot orientation must not fight the sled removal direction |
| Software interface | `LogSink` implementation writing the schema CSV with CRC-16 rows |
| Test required | B-06 data logging, B-13 long-duration logging, B-14 power-down / data preservation |
| Evidence before flight use | no dropped frames over the longest planned log; damaged-row behaviour after a power cut |
| Existing example class | "microSD SPI breakout + industrial / high-endurance card" — `avionics/electronics.csv`, unverified |

## 9. Telemetry radio (optional subsystem)

| Item | Requirement |
|---|---|
| Required interface | SPI; 41-byte packets at 2–5 Hz |
| Voltage / interface constraints | 3.3 V; **band and power must be legal where the rocket is flown**; antenna impedance and length documented |
| Physical envelope | ≤ 20 × 7 × 28 mm placeholder; antenna route not modelled (steel rods run alongside) |
| Approximate mass budget | within EL-AV 59 g (assumption) for the airborne module |
| Mounting | module on the sled; antenna away from the rods, battery and GNSS antenna |
| Software interface | radio driver behind `HardwareTelemetryLink` (`transmit` / `receive`) |
| Test required | B-07 packet generation, B-08 packet integrity, B-09 ground-station link, B-10 packet-loss handling, and a range walk test (existing plan item T-14) |
| Evidence before flight use | measured packet-loss rate at ≥ 2× the expected distance; licence / band legality confirmed |
| Mentor / range | **REQUIRES MENTOR/RANGE REVIEW**: frequency coordination and power limits |
| Existing example class | "Semtech SX127x LoRa module pair — ONLY on a band/power legal in your country" — `avionics/electronics.csv` |

## 10. Separation sense, annunciation, camera

| Item | Requirement |
|---|---|
| Separation breakwire | thin wire across joint I-03 into a GPIO **input** with pull-up; test B-02 continuity, plan item T-15 |
| Buzzer + LED | GPIO annunciation only; audible after landing; test B-01 |
| Camera (optional) | self-contained recorder with its own battery, in `cad/parts/PL-203_camera_cradle.scad`; mass placeholder 35 g (USER); no electrical connection to the flight computer |
