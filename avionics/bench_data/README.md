# avionics/bench_data/

Where **bench recordings** from real avionics hardware are kept, once such hardware exists.

> **There is no real bench data in this repository yet.** `example_bench_record.csv` is a **column template whose
> values are synthetic** (generated by the simulated sensors), so its `data_source` column says `SYNTHETIC`. Nothing in
> this folder is a measurement, flight data, or evidence that any component works. ASTRA-66 is NOT flight certified.

## Format

A bench record uses the same sensor-level CSV format as the replay input (`avionics/DATA_FORMAT.md` §3), so the same
processing pipeline reads synthetic, bench and (later) flight data without any change to the processing code:

```bash
python simulation/avionics_replay.py avionics/bench_data/<your-record>.csv --out simulation/results/<name>
```

Columns: `timestamp`, `data_source`, then the sensor fields. Rules that matter for a real recording:

- **`data_source` must be `BENCH` in every row** of a genuine bench recording (`SYNTHETIC` only for generated values,
  `FLIGHT` is disabled in software until a real flight record exists: `avionics/firmware/data_source.py`).
- One row per tick on a uniform grid; empty cell = no sample from that sensor at that tick.
- Record what the sensor produced, including implausible values: validation is the flight computer's job and rejecting
  bad data is one of the things the bench test checks.
- Do not edit values by hand. If a value is wrong, note it in the meta file instead.

## Meta file

Every recording needs a sidecar `<name>.meta.json` next to it. Fill in only what was actually done:

```json
{
  "title": "ASTRA-66 bench record",
  "data_source": "BENCH",
  "test_id": "B-03 (see documentation/AVIONICS_BENCH_TEST_PLAN.md)",
  "date": "YYYY-MM-DD",
  "operator": "name",
  "mentor_present": false,
  "hardware": {
    "flight_computer": "board and revision",
    "imu": "part number, breakout revision",
    "barometer": "part number",
    "gnss": "module and antenna",
    "temperature": "part number or 'barometer internal'",
    "battery": "cell type and capacity",
    "storage": "card type",
    "radio": "module, band and power setting (must be legal where operated)"
  },
  "firmware": {"commit": "git commit", "log_rate_hz": 100, "notes": ""},
  "setup": "bench layout, orientation, what was moved or heated, reference instruments used",
  "reference_instruments": ["multimeter make/model", "reference barometer", "scale"],
  "known_issues": ["what went wrong, loose connector, etc."],
  "values_are_measurements": true
}
```

Set `"values_are_measurements": false` for any file whose values were generated, as in the example template.

## Regenerating the example template

```bash
python simulation/avionics_replay.py --make-bench-example
```

It writes 10 s of synthetic pad data (50 Hz) with no injected faults, purely to show the column layout.
